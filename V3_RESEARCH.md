# Research, baseline and evaluation protocol

## What the project evidence establishes

The starting dashboard labels itself 2.9.0. The current GitHub source used for this review is f5f899f3ccd253b0cc180ab9930344adc1365c33. Fourteen differing source/test/document files from the supplied ZIP were identifiable as earlier Git versions. The GitHub tree also has the newer chart studies, dealer heat map and paired adaptive exits. Historical installers and nested release bundles in the attachment are not part of the new runtime. Its only runtime database in the archive is a Schwab OAuth store. It was excluded. There is no continuous trading journal in that attachment.

At that revision, monitor_data/signal_history.json holds 500 selected records across November 19, 20, 23, 24, 25 and 27. Their counts are 382 MOVE WATCH, 86 EMA TREND, 9 ENTER LONG, 7 ENTER SHORT and 16 EXIT. Entries in an alert mirror do not establish paper fills or returns. The bounded research snapshot is dated November 13 at 20:45 UTC. For each of SPY and SPX it contains 28 decisions, 44 hedge snapshots and zero candidates. QQQ is absent. No price, flow or option histories were synthesized to bridge these gaps.

Audit of actual control flow:

- The original monitor already watches completed 1m/3m/5m/10m price changes. Its 15-minute same-direction cooldown and deduplication apply to those watches. It would be inaccurate to attribute every late alert to five-minute flow.
- Standard entry uses aligned closed candles, flow, option spreads, risk/reward and session filters. A single delayed provider clock can keep the combined setup waiting. A fresh receipt alone cannot repair stale market time. The new detector produces an independently timestamped advisory result during those waits.
- The baseline shared mirror selects transitions and caps each group. Its selection cannot supply the denominator for missed events. The new private journal includes fresh warm-up rows where available, WAITs, option alternatives and subsequent quote samples.
- The baseline paper engine has an adaptive-exit comparison already. Existing score, broker, entitlement, position-size and exit paths were inspected and retained. V3 can change what the user sees before an entry without moving the entry threshold.
- A minimum of seven contiguous one-minute candles is needed for the new scaled detector. Shocks before that point or during data loss have incomplete coverage. First-touch direction is indeterminate if both barriers are crossed within the first touching OHLC bar.

Hypotheses awaiting forward tests include whether a pressure watch beats the existing price watch, whether absorption helps distinguish reversals, whether removing any five-minute confirmation improves net returns, whether ES leads after receipt latency, and whether skew-linked premium scenarios improve ranking after execution costs.

## Contract chart checks in RC2

A first pass at the ETF chart showed large one-minute Gamma changes under a fixed underlying and IV. An option lattice has piecewise-linear prices between grid nodes, which makes repeated small price bumps a poor way to draw Gamma. RC2 estimates Delta and Gamma from neighboring lattice levels and smooths continuation in the last time step. It can use analytic spatial Greeks when the modeled carry rules out an early-exercise premium. Early exercise remains available where the model supports it. The controlled before-and-after measurements and conditions are in VALIDATION.txt in the release archive. These tests evaluate numerical stability. Live bid/ask behavior around dividends or exercise still requires market observations. [Broadie and Detemple, American Option Valuation](https://doi.org/10.1093/rfs/9.4.1211)

A series can stop trading before its payoff is fixed. The contract chart distinguishes the AM SPX last-trading reference from the next opening settlement reference. SPXW uses the PM close, including the shortened-session calendar where applicable. A modeled value after last trading is a valuation scenario. [Cboe SPX specifications](https://www.cboe.com/tradable-products/sp-500/spx-options/spx-specifications)

## Acceptance protocol set before collecting a new forward sample

1. Freeze the source, configuration, symbol list, cost model and barrier definition. Use the same sessions, providers and eligible windows across V2, V3 and challengers. Record outages, open warm-up, ambiguous bars and contract-quote match rates. Compare all covered events, including those with no warning.
2. A model-independent price event uses a preceding volatility scale, a five-minute window and realized one-minute high/low touches. The first nonoverlapping touch defines direction. Timestamping cannot resolve an intrabar sequence. Separate first-touch metrics by independent event from origin-count metrics on overlapping horizons. The latter are correlated.
3. Start development benchmarking at 20 sessions and 500 classified origins per ticker. Logistic fits the five-minute upside-vs-other target with explicit missingness, an expanding session walk-forward and a final four-session chronological benchmark. The repeating four-day evaluation is development evidence. Reserve a separate future block before production consideration. Stratify counts by session, regime, direction, DTE, spread and time of day.
4. Proposed human review gate for a trading change: at least 40 development sessions, ten new untouched sessions and 100 independent matched events per ticker. Report paired, session-block bootstrap intervals. Require a positive lower 95% bound for change in net expectancy and no increase in false alerts per covered hour or peak-to-trough loss on that held block. Include an adverse execution case adding half a quoted spread on exit. If the gate fails or the sample is sparse, retain the baseline. These review criteria have not been met or executed on customer data.
5. For prices compare conditional mark errors at realized near-time spot/IV separately from errors using the original target and IV. Rank success uses a later tradable bid and initial ask plus modeled fees, including eligible alternatives. Missing later quotes remain unscored and must be shown alongside matched counts. Shadow outcomes cannot establish production fill quality.
6. Neither literature, preview fixtures, synthetic training tests nor the downloaded alert archive supply a measured V3 win rate. There is presently no validated winner or live probability estimate.

The offline evaluator implements a paired day-block bootstrap specifically for five-minute directional-origin recall versus original MOVE WATCH. Use v3_evaluate.py on the private daily Parquet archive. It requires at least ten days for the interval and reports the raw counts. Net-expectancy and drawdown require separate matched executions and an untouched validation block.
